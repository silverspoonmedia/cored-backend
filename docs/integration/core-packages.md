# Core domain packages

A **core domain** can ship as a Composer path package under `packages/{slug}/` instead of living in `app/Domain/{Domain}/`. The point is downstream reuse: a client project installs `silverspoonmedia/navigation` without forking this repo. Extraction moves **where** the code lives, never its contract — namespace `App\Domain\{Domain}\*`, route names, config keys, migration timestamps, and un-namespaced translation keys (`api/navigation.created`) are unchanged. **One package may carry more than one core domain.** A package is a *distribution unit*, not a taxonomy mirror: domains consumed together ship together. `silverspoonmedia/audit` bundles ActivityLog + ErrorLog; `silverspoonmedia/billing` bundles PaymentGateway + **Currency** + Service (one money surface — the vocabulary, the catalog priced in it, the invoice that collects for it); `silverspoonmedia/ai` bundles Inference + Ai, because a rate nobody can bill is not a price. Product domains stay in `app/Domain/{Product}/` and keep their `uninstall.json` contract ([architecture.md](../platform/architecture.md)).

## The kernel is a package too

`silverspoonmedia/platform` carries the code every package imports but no package owns: `App\Support\*`, the Identity hub (`App\Domain\Identity\*`), the HTTP glue (`App\Http\{Controllers,Requests,Resources,Middleware}`), `App\Repositories\*`, `App\Providers\{Encryption,Product,DomainAccess,Settings,Domain\Identity}ServiceProvider`, `App\Rules\*`, `App\Traits\*`, `App\Exceptions\*`. Namespaces are unchanged — extraction moved **where** the file lives, never the `use` line.

- **Every non-kernel package requires it.** `packages/{navigation,notification,audit,billing,ai}/composer.json` carry `"silverspoonmedia/platform": "^1.0"`; `DependencyDirectionTest::test_every_non_kernel_package_requires_the_platform_package()` fails on a package that imports kernel code without declaring it. `DependencyDirectionTest::test_kernel_reaches_a_package_only_through_a_kernel_contract()` holds the other direction with an **empty** burn-down list (there is no allowlist constant to grow), so a package that reaches back into the kernel except through a declared contract fails too.
- **The host requires a range, not `*`.** Root `composer.json` pins each path package with `"^1.0"`; `PackageManifestTest::test_root_requirement_is_a_caret_constraint()` fails on a wildcard (only the VCS dependency `silverspoonmedia/pdf-tools` is exempt, it is pinned to a commit hash). `test_locked_versions_match_package_manifests()` fails when `composer.lock` and `packages/{slug}/composer.json` disagree on a version, and `test_every_package_declares_the_kernel_at_its_own_minor()` fails when a sibling requires the kernel at a different minor than its own `version`. Bumps go through `-Bump` + `composer update silverspoonmedia/* --no-scripts` in the same commit; a manifest bump without the lock refresh is now a red gate, not a silent drift.
- **The host still wins.** Root `composer.json` re-declares `App\Support\`, `App\Http\`, `App\Repositories\`, `App\Domain\Identity\` over `app/`, which is how four product-coupled files stay in the host as overrides: `app/Support/Product/Services/{ProductAnalyticsService,ProductInsightService}.php` and `app/Support/ListActions/Builders/{HashBlocklistQueryRowActions,MicrostockCredentialQueryRowActions}.php`. `PackageOverrideTest` asserts an override file wins the PSR-4 race.
- **`helpers.php` ships once.** `src/Support/Settings/helpers.php` loads through the package's `autoload.files`; the root manifest must **not** list it again or every function is declared twice (fatal on boot).
- **Migrations stay host-owned.** `users`, `password_reset_tokens`, `sessions`, `cache`, `jobs`, `permission_tables`, `system_settings`, `product_*` and `identity_oauth_accounts` live in `database/migrations/` — the package ships the models for a host-owned schema, and its tests build that schema through `App\Support\Testing\KernelSchema`. A host may re-run those migrations from the package by publishing them with `php artisan vendor:publish --tag=silverspoon-platform-migrations`.

## Invariants

1. **The host wins the PSR-4 race.** Root `composer.json` declares `"App\\Domain\\Navigation\\": "app/Domain/Navigation/"` explicitly, so the generated map is `[app/Domain/Navigation, vendor/silverspoonmedia/navigation/src]`. Dropping that line makes every host override dead code, silently — `PackageOverrideTest` asserts it. A bundled package declares **one prefix per domain** it carries.
2. **The kernel never imports a package.** It declares the contract it needs — `PresentedTreeEpoch` for navigation, `DecryptionAuditRecorder` for the decrypt choke point, `ExceptionRecorder` for `bootstrap/app.php`'s `reportable()` — and the package binds it; a host without the package still boots because every call sits behind `app()->bound()`. A core package may import `App\Support\*` and the Identity hub, never a product domain.
3. **The package owns its wiring.** `extra.laravel.providers` auto-discovers the provider, which alone calls `mergeConfigFrom`, `loadMigrationsFrom`, `translator->getLoader()->addPath(__DIR__.'/../resources/lang')`, binds contracts, registers listeners and commands. `bootstrap/*` mentioning the package again is a defect. A bundled package has **one** provider for all its domains.

   Removing a package means removing its **registry entries** too: with the package gone but `config/domains.php` still naming its `routes`, the kernel boots (`php artisan about` works, no package class is referenced) and route registration fails on a missing controller. Clear `bootstrap/cache/{packages,services}.php` first — a stale `packages.php` still names the auto-discovered provider and fails provider load before the real cause is visible.
4. **Every path comes from the registry.** `domainPath()`, `providerPath()`, `apiRoutePath()`, `testsPath()` read `config/domains.php` and fall back to `app/Domain/*`; no caller hardcodes either shape. Bundled domains at the same `path` still name their **own** `routes` file.
5. **A package pins its `version`.** A path repository otherwise infers `dev-{branch}` and `composer update` fails against `minimum-stability: stable` on any feature branch.
6. **Bundling never merges namespaces.** A package with two domains keeps `App\Domain\A\*` and `App\Domain\B\*` as separate PSR-4 prefixes and separate test prefixes; a shared `App\Domain\Audit\*` would have changed every import, which extraction must never do.

## Anatomy

`composer.json` (version, PSR-4 for `src` + `database/{factories,seeders}` + `tests`, `extra.laravel.providers`, `require-dev` = `orchestra/testbench` + `phpunit/phpunit`, `scripts.test`) · `src/` · `routes/{domain}.php` — one per domain, no prefix/name, the host applies them (a single-domain package may use `routes/api.php`) · `config/{slug}.php` · `database/{migrations,seeders,factories}` (original timestamps, `App\Domain\{Domain}\Database\*` namespaces) · `resources/lang/{locale}/**` · `tests/` (`App\Domain\{Domain}\Tests`) · `phpunit.xml.dist` (one suite over the declared `tests/` directories).

A package with a **server-side web route** (OAuth callback, payment return) adds a `web` key to its registry entry and a file named `routes/web-{what}.php` (`packages/billing/routes/web-ipaymu-return.php`, `packages/platform/routes/web-identity-oauth-callback.php`); `routes/web.php` loops `packageWebRoutePaths()` instead of a literal `require`, so the `web` middleware group still wraps it. Non-PHP package data (routing YAML) lives in `resources/` and is addressed from the host config (`config/payment-routing.php` → `packages/billing/resources/routing/price.yaml`).

Host side: `"type": "path"` repository over `packages/*`, a `require` entry per package, the explicit PSR-4 prefix, and a `Package:{slug}` suite per package in `phpunit.xml` — the full run covers every suite in the file, `php artisan test --testsuite=Package:billing` runs one tree alone. `PackageTestSuiteTest` keeps the file and the tree in agreement (a package with tests nobody wired contributes zero assertions, silently) and refuses a directory wired into two suites.

A package's tests run **standalone**: every test extends `App\Support\Testing\PackageTestCase` (Orchestra Testbench), which boots the kernel providers plus the package's own provider, builds the kernel schema through `App\Support\Testing\KernelSchema` and the package's own migrations, and mounts routes straight off each booted provider's package: `routes/*.php` under the `/api/v1` group and `routes/web-*.php` under `web`. In this checkout the registry (`config/domains.php`) decides; a consumer install adds no registry, so the package's own `routes/` directory is the source. Nothing comes from `bootstrap/app.php`, `database/migrations` or `tests/**`, so a consumer who clones a tag can run the same tests. `PackageTestSuiteTest::test_every_package_test_runs_under_the_standalone_base()` and `DependencyDirectionTest::test_no_package_test_imports_a_host_only_fixture()` keep it that way.

The honest limit: a test that needs a **host-assembled extra** route (the kernel's `packages/platform/routes/kernel-{settings,product-activations,domain-access,batch,broadcasting}.php`), a host **fixture** (the audit package's subscriber, the published `lang/{locale}.json` packs) or a **product** row (Microstock AI credits, Archivd quota) stays in `tests/Domain/Core/{Domain}/` under the host `Tests\TestCase`. The kernel's own surface ships whole: `packages/platform/routes/identity.php` and `routes/web-identity-oauth-callback.php` are registry route files, and the seven Identity feature tests (`AuthFlow`, `HcaptchaAuth`, `LoginThrottle`, `UserManagement`, `Lookup`, `ProfileConnectionsApi`, `DiscordOAuthCallbackWeb`) run in the standalone suite against those files.

Each package also carries its own `phpunit.xml.dist` and a `composer test` script (`@php vendor/bin/phpunit`), so `composer install && composer test` inside the package works with no monolith. `scripts/run-standalone-package-suite.php` — `composer test:standalone`, the `standalone-packages` CI job — copies each package to a temporary directory, resolves the siblings from source, installs and runs it; `PackageStandaloneRunTest` asserts the pieces that run needs are present, and the same job runs `scripts/run-consumer-scaffold-check.php` against `client-scaffold/` (which also executes the scaffold's own `tests/` inside the copy). Locale guards scan `lang/` **plus** `packages/*/resources/lang` (`locale_scan_lang_roots()`); `LocaleParityTest` reads both trees.

A packaged domain's config file usually moves with it (`packages/notification/config/notification.php`, `packages/audit/config/errorlog.php`). The exception is a **published vendor config the host owns**: `config/activitylog.php` stays in the host because it is Spatie's file, merged last, with `sensitive_properties.*` in it — the same package can therefore own one config and leave another in place. The kernel ships `spa-routes.php`, `localization.php`, `services.php` and `hcaptcha.php` (merged shallow by `KernelServiceProvider` / `IdentityServiceProvider`, host wins) because Navigation, Identity and the Discord callback read them on a kernel-only install; `packages/billing/config/services.php` carries the `frankfurter` FX block for the same reason, merged by `BillingServiceProvider`. A product name inside `packages/platform/config/*` is drift the manifest reference scan reports.

That split only holds while the kernel side stays a **subset** of the host side, and `KernelConfigParityTest` proves it: `spa-routes.menu`/`deny` kernel entries must exist in the host list (a product domain may add entries, the kernel may not invent one), `localization.php` must be the same document in both places, every top-level `services` block the kernel ships must exist on the host, and `frankfurter` resolves from the billing merge while the host carries no copy of it. The other half of an override hook is the PSR-4 race: the root re-declares `App\Support\`, `App\Http\`, `App\Repositories\`, `App\Traits\`, `App\Rules\`, `App\Exceptions\` and `Database\{Factories,Seeders}\` ahead of the package entry, and `PackageOverrideTest::test_kernel_override_prefixes_resolve_host_first()` writes one probe class per prefix to prove the host copy still wins. Invariants: [architecture.mdc](../../.cursor/rules/architecture.mdc).

A product `uninstall.json` that cited a moved file records the package path (`packages/navigation/database/seeders/MenuSeeder.php`, `packages/billing/tests/Service/Unit/Services/ServiceEntitlementServiceTest.php`) — removing the product never removes the package.

## Seams a bundled package needs

A core package may import `App\Support\*` and the Identity hub — never a product domain ([architecture.mdc](../../.cursor/rules/architecture.mdc)). When the domains being packaged are *about* products (billing fulfills quotas into `Archivd` and `Microstock`), the coupling moves into kernel contracts the kernel declares and the product implements:

| Contract | Kernel owner | Package use | Product side |
|---|---|---|---|
| `Support\Billing\Contracts\FulfillmentHandler` + `FulfillmentContext` | `Support\Billing\FulfillmentRegistry` (singleton) | `ServiceFulfillmentService` / `ServiceEntitlementLifecycleService` call `forTarget($target)`, never a product class | `Archivd\Support\Billing\ArchivdFulfillmentHandler`, `Microstock\Support\Billing\MicrostockFulfillmentHandler` register in their provider behind `app()->bound()` |
| `Support\Billing\Contracts\TierObserver` | same registry (`registerTierObserver`) | reports derived tier moves (`paid`/`grace`/`free`) | `ArchivdTierObserver` moves the product analytics tier |
| `Support\ActivityLog\{SubjectAliasRegistrar,SubjectLabelRegistrar}` | `packages/audit` binds `SubjectTypeResolver` / `SubjectLabelRegistry` | the trail maps `?subject=menu` and renders `subject_label` without naming a sibling package | `NavigationServiceProvider` registers `menu` → `Menu::class` and `MenuSubjectLabelPresenter`, both behind `app()->bound()` |
| `Support\Notifications\Contracts\NotificationDispatcher` | `packages/notification` binds the adapter | emits a **string** type (`service.entitlement.grace`) | adapter maps the string to `NotificationType` |
| `Support\Broadcasting\Contracts\ChannelRegistrar` | `routes/channels.php` loops it behind `app()->bound()` | registers `payments.invoice.{id}` / `payments.routing` / `payments.admin` / `services.catalog` | host keeps `settings.currencies`, `logs.*`, RBAC |
| `Support\Encryption\Contracts\LegacyColumnMigrator` | `Support\Encryption\EncryptionMigrationRegistry` | registers the `invoices.gateway_request_payload` / `gateway_response_payload` migrator | — (keeps `EncryptionMigrateP0Command` free of `Invoice`) |
| `Support\Ai\Contracts\AiUsageLedger` | bound by the product provider | `InferenceUsageAnalyticsService` reads the event model, its eager-load relations and USD formatting | `Microstock\Support\Ai\MicrostockAiUsageLedger` |
| `Support\Ai\AiUsageConsolidatorRegistry` + `Contracts\AiUsageConsolidator` | `AppServiceProvider` singleton | `InferenceCatalogService::syncProviderRates()` consolidates the ledger registered **under the provider slug** | `Microstock\Support\Ai\MicrostockAiUsageConsolidator` registers with `config('microstock.ai.inference_provider_slug')` |
| `config('ai.usage_event_resource')` | config key, published by the product provider | the dashboard controller renders the product's row class | `Microstock\Support\Ai\MicrostockAdminUsageEventResource` |

The AI seam is the one place a **config key** stands in for a contract: a JSON resource is a class instantiated per row, and a kernel interface returning a class-string would only add a hop. `AiServiceProvider` ships `'usage_event_resource' => ''`; with no product installed the admin usage dashboard returns an empty page instead of a package import. An EMPTY registry is a legal state — with no product installed the package runs the same code and every hook is a no-op (`PackageOverrideTest::test_kernel_boots_without_the_audit_package()`), and a registry of **class strings** rather than instances keeps an Octane worker from pinning a product service.

## Distribution

The monolith stays the **only source**. `packages/{slug}/` is edited here, required here through the `path` repository, and installed here as a junction — nothing about day-to-day work changes because a mirror exists.

Each package also has a **read-only mirror repo** in the `silverspoonmedia` org — `github.com/silverspoonmedia/{platform,navigation,notification,audit,billing,ai}` — so a consumer can `composer require` it without access to this repo. The consumer workflow itself — template, core-only registry, `vendor/` paths, override hooks, the config split — is [client-project.md](client-project.md).

Rules:

1. **Never push to a mirror by hand.** A mirror is a one-way derivative produced by `scripts/publish-packages.ps1`; a manual commit there is lost on the next publish.
2. **Release is a tag, not a branch.** Publish with `scripts/publish-packages.ps1 -Version vX.Y.Z -Bump` from `main`; `-Bump` writes that version into every selected `packages/{slug}/composer.json` and commits it, then the script creates the repo if missing, runs `git subtree split --prefix=packages/{slug}`, pushes the split to the mirror's `main`, strips the `version` field, and tags that commit. `scripts/verify-mirrors.ps1 -Tag vX.Y.Z` then compares every mirror's `main` with a local subtree split and its newest tag with the pinned version — non-zero when anything drifted.
3. **`version` exists only in the monolith.** A path repository needs it ([invariant 5](#invariants)); a tagged VCS repository must not have it, or every tag reports `1.0.0` and `^1.0` cannot tell releases apart.
4. **`tests/` never ships in the tag — but it runs.** Each package carries a `.gitattributes` with `export-ignore` for `tests/` and `.github/`, so the tarball is source only. The source repo keeps `tests/` with its `phpunit.xml.dist`, so a clone of the mirror runs `composer install && composer test`; `composer test:standalone` proves that path for all six packages. **A consumer installs by VCS**, because the mirrors are private: `{"type": "vcs", "url": "https://github.com/silverspoonmedia/billing.git"}` plus `"silverspoonmedia/billing": "^1.0"` — Composer needs a token that can read the org. The consumer-side recipe is [client-project.md](client-project.md).
5. **A mirror is not a PR target.** Two-way contribution would need a different model (the package repo as source of truth); this repo deliberately keeps the source, so a change starts here.
6. **`KernelServiceProvider` is registered by the consumer, not auto-discovered.** It owns what the host's `AppServiceProvider` owns here (four seam registries, `EloquentCrudRepositoryInterface`, `CorsService`), the five kernel config merges, and the two commands that edit nothing durable — `domain:list` and `encryption:flush-decrypted-cache` (registered in `boot()` from `packages/platform/src/Console/Commands/`; `domain:make` / `domain:remove` rewrite host trees and stay host-only) — all behind `! $this->app->bound(...)` guards, so one provider answers per install. Since tag `v1.0.5` a consumer runs both from `vendor/`; `KernelConsoleCommandsTest` asserts that wiring inside the package. It stays out of `extra.laravel.providers`: auto-discovery would boot it here too and discard a resolved registry. `ConsumerScaffoldTest` asserts the scaffold lists it in `bootstrap/providers.php`.

7. **No git subtree.** A consumer never vendored this repo as `core/`: `update-core.sh`, `push-core.sh` and `client-subtree.md` are deleted, and `tests/Unit/Documentation/CoreScriptTest.php` fails if they return. A subtree snapshot could not be upgraded; the packages are the upgrade path. **Adding one:** `git mv` each piece (never copy: history follows), rewrite only the `Database\*` and `Tests\*` namespaces, write `composer.json` (version, `require-dev` with Testbench, `scripts.test`, PSR-4 for `tests/`), add `phpunit.xml.dist`, fold the old provider body into the package provider, add the registry entry + `require` + PSR-4 prefix, then delete the host copies and `bootstrap/*` references. Verify with `composer update silverspoonmedia/*`, `composer dump-autoload`, `php artisan domain:list`, `php artisan route:list --path=api/v1`, `php artisan test --testsuite=Package:{slug}`, `php scripts/run-standalone-package-suite.php {slug}`, and the locale parity scripts — the route count must equal the pre-move baseline. Windows: `"symlink": true` produces a junction and works here; if it ever fails, set `"symlink": false` and re-run `composer update silverspoonmedia/*` after every change under `packages/`.
