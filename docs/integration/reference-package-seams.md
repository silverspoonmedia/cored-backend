# Reference — package seams and the distribution rules

Deep dive for [core-packages.md](core-packages.md). Two halves: the seams a **bundled package** reads from a product, and the invariants that keep the packages publishable. Neither repo in this workspace is the source of a package — `monolith` is, and this fork consumes its tags — so every rule below is stated with the repo it applies to.

## Seams a bundled package needs

A core package may import `App\Support\*` and the Identity hub — never a product domain ([architecture.mdc](../../.cursor/rules/architecture.mdc)). When the packaged domains are *about* products, the coupling moves into kernel contracts the product implements. "Product side" is the living line's implementation; in this fork no product exists, so every registry stays empty and every hook is a no-op.

| Contract | Kernel owner | Package use | Product side (living line) |
|---|---|---|---|
| `Support\Billing\Contracts\FulfillmentHandler` + `FulfillmentContext` | `Support\Billing\FulfillmentRegistry` (singleton) | `ServiceFulfillmentService` / `ServiceEntitlementLifecycleService` call `forTarget($target)`, never a product class | `Archivd\Support\Billing\ArchivdFulfillmentHandler`, `Microstock\Support\Billing\MicrostockFulfillmentHandler` register in their provider behind `app()->bound()` |
| `Support\Billing\Contracts\TierObserver` | same registry (`registerTierObserver`) | reports derived tier moves (`paid`/`grace`/`free`) | `ArchivdTierObserver` moves the product analytics tier |
| `Support\ActivityLog\{SubjectAliasRegistrar,SubjectLabelRegistrar}` | `vendor/silverspoonmedia/audit` binds `SubjectTypeResolver` / `SubjectLabelRegistry` | the trail maps `?subject=menu` and renders `subject_label` without naming a sibling package | `NavigationServiceProvider` registers `menu` → `Menu::class` and `MenuSubjectLabelPresenter`, both behind `app()->bound()` |
| `Support\Notifications\Contracts\NotificationDispatcher` | `vendor/silverspoonmedia/notification` binds the adapter | emits a **string** type (`service.entitlement.grace`) | adapter maps the string to `NotificationType` |
| `Support\Broadcasting\Contracts\ChannelRegistrar` | `routes/channels.php` loops it behind `app()->bound()` | registers `payments.invoice.{id}` / `payments.routing` / `payments.admin` / `services.catalog` | host keeps `settings.currencies`, `logs.*`, RBAC |
| `Support\Encryption\Contracts\LegacyColumnMigrator` | `Support\Encryption\EncryptionMigrationRegistry` | registers the `invoices.gateway_request_payload` / `gateway_response_payload` migrator | — (keeps `EncryptionMigrateP0Command` free of `Invoice`) |
| `Support\Ai\Contracts\AiUsageLedger` | bound by the product provider | `InferenceUsageAnalyticsService` reads the event model, its eager-load relations and USD formatting | `Microstock\Support\Ai\MicrostockAiUsageLedger` |
| `Support\Ai\AiUsageConsolidatorRegistry` + `Contracts\AiUsageConsolidator` | `AppServiceProvider` singleton | `InferenceCatalogService::syncProviderRates()` consolidates the ledger registered **under the provider slug** | `Microstock\Support\Ai\MicrostockAiUsageConsolidator` registers with `config('microstock.ai.inference_provider_slug')` |
| `config('ai.usage_event_resource')` | config key, published by the product provider | the dashboard controller renders the product's row class | `Microstock\Support\Ai\MicrostockAdminUsageEventResource` |

The AI seam is the one place a **config key** stands in for a contract: a JSON resource is a class instantiated per row, and a kernel interface returning a class-string would only add a hop. `AiServiceProvider` ships `'usage_event_resource' => ''`; with no product installed the admin usage dashboard returns an empty page instead of a package import. An empty registry is a legal state — the package runs the same code and every hook is a no-op (`PackageOverrideTest::test_kernel_boots_without_the_audit_package()` in the living line) — and a registry of **class strings** rather than instances keeps an Octane worker from pinning a product service.

Here every one of those registries is empty: there is no product provider to fill it, so a billing fulfillment lookup finds nothing and the entitlement lifecycle stops at "no handler". That is the intended fork state, not a broken install — do not "fix" it by editing a package.

## Distribution rules

`monolith` is the **only source**. It edits `packages/{slug}/`, requires it through a `path` repository, and installs it there as a junction; nothing about its day-to-day work changes because a mirror exists. This fork is on the other side of that boundary: it has none of those trees, and every rule below marked *(living line)* describes work that does not happen here.

Each package also has a **read-only mirror repo** in the `silverspoonmedia` org — `github.com/silverspoonmedia/{platform,navigation,notification,audit,billing,ai}` — so a consumer can `composer require` it without access to the source repo. This fork declares the six as `"type": "vcs"` repositories and requires `^1.2`; the consumer recipe and the override hooks are [client-project.md](client-project.md).

1. **Never push to a mirror by hand.** A mirror is a one-way derivative produced by `scripts/publish-packages.ps1` *(living line)*; a manual commit there is lost on the next publish.
2. **Release is a tag, not a branch.** *(living line)* Publish with `scripts/publish-packages.ps1 -Version vX.Y.Z -Bump` from `main`; `-Bump` writes that version into every selected `packages/{slug}/composer.json` and commits it, then the script creates the repo if missing, runs `git subtree split --prefix=packages/{slug}`, pushes the split to the mirror's `main`, strips the `version` field, and tags that commit. `scripts/verify-mirrors.ps1 -Tag vX.Y.Z` then compares every mirror's `main` with a local subtree split and its newest tag with the pinned version — non-zero when anything drifted. Re-running for a published tag replays the strip commit on the new `main` and keeps the tag on its original commit, so a consumer that already locked that tag still resolves it.

    **The `v1.2` line.** `v1.2.1` re-cut the same `en`+`id` pack pruning after a kernel presentation change landed post-tag, so the mirrors track source again; `v1.2.0` pruned them in the first place. Consumers keep the `^1.2` range. **The `v1.1` line** published the fork seams: `SettingContributor` + `MenuContributor` (a product registers its settings groups and menu nodes from its own provider, so a product-free host boots with an empty catalog and no product group), `storage.upload_proxy.*` (a product publishes its upload proxy into the kernel's `storage` group instead of the kernel reading the product's config), `ai.consumers` / `ai.ledger_fk_targets` (the AI package names no product), and the SPA `FeatureModule` registry. *(living line)* Every manifest and the scaffold require the current line — `^1.2` as of `v1.2.1` — and `PackageManifestTest` keeps the siblings on the kernel's own minor. This fork's root requirement is `^1.2` for the same reason; `client-scaffold` is not checked out here, so the scaffold-side guard does not run.
3. **`version` exists only in the living line.** A path repository needs it ([invariant 5](core-packages.md#invariants)); a tagged VCS repository must not have it, or every tag reports `1.0.0` and the caret cannot tell releases apart. This install resolves the tag, so `vendor/silverspoonmedia/*/composer.json` has no `version` key — never add one.
4. **`tests/` never ships in the tag — but it runs, in the source.** Each package carries a `.gitattributes` with `export-ignore` for `tests/` and `.github/`, so the tarball is source only. The source repo keeps `tests/` with its `phpunit.xml.dist`, so a clone of the mirror runs `composer install && composer test`, and `composer test:standalone` proves that path for all six packages *(living line)*. A consumer installs by VCS, because the mirrors are private: `{"type": "vcs", "url": "https://github.com/silverspoonmedia/billing.git"}` plus `"silverspoonmedia/billing": "^1.2"` — Composer needs a token that can read the org, and `composer update` locks the tag with the mirror's commit as `reference`. `scripts/run-vcs-consumer-check.php` *(living line)* is the proof: it copies `client-scaffold`, installs from the six mirrors with a GitHub token, and asserts the lock, the core-only registry, the mounted URIs and one booted request.
5. **A mirror is not a PR target.** Two-way contribution would need a different model (the package repo as source of truth); the source repo deliberately keeps the source, so a change starts there. Here that means: a wrong or missing package behavior is reported upstream, never patched in `vendor/`, and never worked around by copying a class into `app/Domain/` unless the override is meant to persist.
6. **`KernelServiceProvider` is registered by the consumer, not auto-discovered.** It owns what the living line's `AppServiceProvider` owns (the seam registries, `EloquentCrudRepositoryInterface`, `CorsService`), the five kernel config merges, and the two commands that edit nothing durable — `domain:list` and `encryption:flush-decrypted-cache` (registered in `boot()` from `vendor/silverspoonmedia/platform/src/Console/Commands/`; `domain:make` / `domain:remove` rewrite host trees and stay host-only) — all behind `! $this->app->bound(...)` guards, so one provider answers per install. Since tag `v1.0.5` a consumer runs both from `vendor/`; `KernelConsoleCommandsTest` asserts that wiring inside the package. It stays out of `extra.laravel.providers`: auto-discovery would boot it here too and discard a resolved registry. This fork lists it in `bootstrap/providers.php`; dropping that line leaves the kernel bindings unregistered and every seam unresolved.
7. **No git subtree.** A consumer never vendored the source repo as `core/`: `update-core.sh`, `push-core.sh` and `client-subtree.md` are deleted, and `tests/Unit/Documentation/CoreScriptTest.php` fails if they return. A subtree snapshot could not be upgraded; the packages are the upgrade path. **Adding a package** *(living line)*: `git mv` each piece (never copy: history follows), rewrite only the `Database\*` and `Tests\*` namespaces, write `composer.json` (version, `require-dev` with Testbench, `scripts.test`, PSR-4 for `tests/`), add `phpunit.xml.dist`, fold the old provider body into the package provider, add the registry entry + `require` + PSR-4 prefix, then delete the host copies and `bootstrap/*` references. Verify with `composer update silverspoonmedia/*`, `composer dump-autoload`, `php artisan domain:list`, `php artisan route:list --path=api/v1`, `php artisan test --testsuite=Package:{slug}`, `php scripts/run-standalone-package-suite.php {slug}`, and the locale parity scripts — the route count must equal the pre-move baseline. Here, consuming a new package is one `require` line, one `vcs` repository entry, one `config/domains.php` entry and one PSR-4 prefix.
